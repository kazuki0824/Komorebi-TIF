# TV Input Framework 視聴機能

## 目的・正本と責務境界

KomorebiはAndroid標準のTV Input Framework（TIF）を介し、OSに登録された任意のTvInputService（TIS）を利用する汎用視聴クライアントとする。特定TIS、HAL、チューナードライバ、CAS、独自のprovider-data形式に依存しない。最初の受入れ対象は [kazuki0824/tv PR #116](https://github.com/kazuki0824/tv/pull/116) だが接続先を限定しない。

本書はKomorebi側の連携仕様・導入手順・受入れ条件の正本。PR本文はその要約と検証状況だけを持ち、レビュー対応履歴はGitHubレビュースレッドに残す。KomorebiはTuner SDK/HALやCASを直接操作せず、SI/EIT/ARIB字幕の解析・復号を重複実装しない。

## TV入力・チャンネルの登録と識別

- 入力は`TvInputManager.tvInputList`から列挙し、非表示の入力は除く。TISのpackage/classは固定しない。
- チューナーは許可された`TvContract.Channels`を用い、所有`COLUMN_INPUT_ID`と行IDを合わせて保持する。表示は`browsable`かつ`searchable`の行に限定し、ワンセグなど特定サービスを独自に除外しない。
- 局ロゴはTISがTvProviderに登録した画像を`TvContract.buildChannelLogoUri(channelUri)`で参照し、`ContentResolver.openAssetFileDescriptor(uri, "r")`によって読取可能な場合のみ`content://` URIを既存ロゴ表示経路に返す。読み取り前に公開チャンネルのinputId・行ID・browsable・searchableを再確認し、別入力のロゴへ誤接続しない。パススルー入力・未公開・権限未許可・画像未登録は空表示とする。Komorebi自身はCDT解析やロゴ作成を行わない。画像未登録を恒久キャッシュせず、TIS側がロゴを後から登録すれば再取得できるようにする。
- HDMIなどの`TvInputInfo.isPassthroughInput`は実チャンネル行を生成せず`TvContract.buildChannelUriForPassthroughInput()`で選局する。
- 選局直前に登録入力、row所有者、可視性を再照合する。保存済み入力が削除されても別入力へ黙って切り替えない。
- TIFチャンネルは`tif:`から始まる完全な`channel.id`（所有するinputIdを含む）が同一性の正本。ONID/SIDが等しくても別のTIS・HDMIへ置換しない。
- 最終視聴履歴の保存時は、TIFだけ`channelId`一致の旧行を置換する。従来ネットワークバックエンドはONID/SIDによる重複抑止を維持するが、TIFの履歴行は削除しない。起動時の`LAST_WATCHED`は現在のbackendに合う行へSQLで絞り込んだ後に最新10件の上限を適用し、他backendの履歴に押し出されないようにする。
- ホーム履歴からの再選局では、登録済みの現在のチャンネル一覧との完全な`channel.id`一致を要求する。削除済みTIF入力の履歴は表示しない。別入力への黙ったフォールバックは禁止する。
- 同じ識別規則をプロ野球タブからのTIF選局にも適用し、現存しないチャンネルへの遷移を抑止する。
- 同名・同番号の局を複数TIS入力が公開する場合は、入力名の一致にかかわらずライブ／ミニ一覧／番組表の表示名の先頭に同じ短い入力識別番号を付け、OS提供の入力名も併記する。HDMI等のパススルー入力も同じラベルが重複する場合は先頭に短い識別番号を付ける。選局には完全なinputIdを使用する。
- 起動チャンネルにTIFの保存済みinputIdを含む完全な`channel.id`を用いる。入力削除・スキャン行0件でも他入力を自動選局せず、起動判定を完了してホームとセットアップ導線へ進める。
- 権限未許可でチューナー入力がある場合、HDMIだけを取得できても完全取得と扱わない。チューナーのみでも一覧を空としてホームと設定・権限案内へ進めるが、保存IDの自動選局は許可後の正常取得まで保留する。最後のTV入力が削除され入力0件でもホーム・SMB・入力再設定へ進める。ライブタブは取得中と取得済み0件を区別し、後者は登録／スキャン／権限設定を案内する。

## 視聴とリモコン操作

- `TvView.tune(inputId, channelUri)`を使い、TIF URIをMedia3/ExoPlayerのURLへ渡さない。
- `LivePlayerScreen`はTIFとネットワーク再生を分離し、TIF時にMedia3用ViewModel/JNIを初期化しない。バックエンド初回DataStore値が確定するまでプレイヤー生成を待つ。
- D-padは子の操作Buttonへ優先して渡し、親の`onPreviewKeyEvent`で横取りしない。操作帯は`showOverlay`で表示・非表示を制御し、決定キーで再表示する。長い入力局名・音声説明には表示幅と省略を適用し、狭い画面では操作ボタン列を水平スクロールできるようにする。
- `onContentBlocked`時は端末の保護者設定と再選局を案内し、無認証の解除機能を作らない。
- `onTracksChanged`の音声IDで`TvView.selectTrack(TYPE_AUDIO)`を実行し、確定表示は`onTrackSelected`を正本とする。同じ言語・説明ラベルが衝突する音声だけ表示番号を併記し、主／副音声を推測しない。TIF字幕の初期状態は既存の「ライブ字幕の初期設定」（ON/OFF）を用い、視聴中の切替は引き続きTIF APIを利用する。
- 字幕トラックは`TvView.TvInputCallback.onTracksChanged()`の`TYPE_SUBTITLE`から取得する。字幕言語の切替は`TvView.selectTrack(TYPE_SUBTITLE, trackId)`でTISへ要求し、確定した選択IDは`onTrackSelected()`を正本とする。字幕を有効にしたときのみ複数トラックの切替ボタンを有効化する。字幕トラックがない場合は言語選択ボタンを表示しない。字幕ON/OFFは従来どおり`setCaptionEnabled()`を使う。これらのAPI呼出例外は黙殺せず画面に通知するが、TISでの実表示成功をAPI呼出成功だけから推測しない。
- TV入力を解決できないときは入力確認エラーのみ表示し、生成されない`TvView`の「映像受信待ち」を重ねない。TIF視聴中の入力削除でチャンネル候補0件になった場合は、空のミニ一覧を開かず操作帯へ戻れるようにする。
- Android TVのON_STOPでTvViewを解放し、ON_RESUMEでも親は選局中TIFの`channel.id`を保持する。子がON_STARTで再選局する。
- EPGなしのTIF局は「番組情報なし」、HDMI等パススルーは入力名を表示し、「放送休止中」と誤表示しない。
- **どのバックエンドへの切替でも**旧ネットワーク録画・ライブ選局、復帰状態、操作帯を解放し、旧録画IDを新バックエンドのストリームURL解決へ渡さない。SMB再生はバックエンド非依存として維持し、TIFへ切り替える際は録画・予約オーバーレイも終了する。

## 番組表・時刻・ジャンル・料金表示

- 許可された`TvContract.Programs`を既存EPGモデルへ写像する。番組が未公開でも視聴チャンネルは保持し、独自のSI/EIT収集エンジンは作らない。
- TvProvider時刻はepochのまま保存し、表示モデルへの投影時に端末`ZoneId.systemDefault()`へ変換する。04:00放送日境界を維持する。
- TIFの放送ジャンルは公開 `TvContract.Programs.COLUMN_BROADCAST_GENRE` を `Genres.decode()` して扱う。#116の複数ARIBジャンルを1要素へ連結する形式は、認識できる `、ARIB(0x.../0x...):` 境界だけ分割し、各ジャンルの大分類・中分類を独立して保持する。他のTISが公開した未知の文字列はそのまま保持する。
- **解釈できた**broadcastの具体分類がある場合はそれを優先する。未知のbroadcast値は原文を保持したうえで、独立したcanonical分類も補完する。ARIBの具体的なアニメ分類が解釈できた場合は、粗いcanonicalのENTERTAINMENTから「バラエティ」を重複追加しない。公開TvProvider列以上のARIB EIT処理はKomorebiで重複実装しない。
- `COLUMN_SCRAMBLED` は **料金区分（無料／有料）ではなくスクランブル有無** を表す。API非対応／NULL／未知値を `is_scrambled=null` として保持する。既存の `is_free` はネットワークAPI互換のBooleanなのでTIFの料金判定には使わない。
- TIFは料金情報がないため、設定画面で「有料放送を除外」を非対応と表示し、ホームのピックアップでもTIFだけ料金による除外を適用しない。番組詳細にはスクランブルのあり／なし／情報なしと料金区分不明を表示する。既存ネットワークbackendのフィルタ動作は維持する。
- 固定のARIBジャンル認識正規表現2本とcanonical表示名対応表は一度だけ生成し、従来の公開ジャンル変換結果は変更しない。
- ライブの現在番組は`start <= now && end > now`、次番組は`start > now`とし、次番組に固定6時間の探索上限を置かない。AOSP `TvContract.Programs`の開始時刻昇順を使い、最初の有効な未来番組が確定したらカーソル走査を終了する。現在・次の最大2行のみ詳細とジャンルを投影し、EPG一覧は要求範囲の全件を扱う。

## バックエンド切替・同期と既存機能

- KonomiTV／EDCB／EPGStationのネットワーク再生経路は変更しない。TIFにはIP／ポートの設定を要求しない。
- 非同期取得では開始時のバックエンドと世代を固定し、強制取得には読み込み要求IDを付与する。結果の公開・保存・読み込み終了前に適用可能な識別子を照合する。旧polling／forceの結果や失敗を現行の画面へ反映せず、停止していたpollingは勝手に再開しない。
- 1回のチャンネル取得では開始時点のbackendを固定し、取得失敗時に別backendへ誤ってフォールバックしない。ロゴ経路も共通のbackend→`LiveProvider`ルーティングを使う。
- EPG検索用先読みはTIFならGR/BS/CS/TV、その他の既存backendなら従来のGR/BS/CS/SKY/BS4Kに限定する。切替後も実際の公開局にある放送種別の選択は保持し、非対応種別だけ公開局の先頭の種別へ戻す。起動時タブもDataStoreの確定backendでタブ名を照合し、非対応の録画予約などはホームへ戻す。backend切替時は10秒待ちを含む先読みJobを取消し、進行中の取得へキャンセルを伝える。TIF入力有無／権限の判定はTvInputServiceを利用するアダプター側にまとめ、ViewModelやEPGキャッシュ側で同じ入力一覧を重複取得しない。
- ピン留めEPGは公開チャンネル一覧で所有inputIdと可視性を確認した後、完全なチャンネルIDで対象を絞ってから対象局だけの番組を取得する。
- TIFのヘルスチェックでは入力一覧と公開チャンネルのみを確認し、疎通確認だけを目的とする全局番組クエリを行わない。権限拒否の通知を隠さない。
- バックエンド切替時はホームのジャンル・野球候補と旧ジョブを無効化し、確定した新backendの結果だけを公開する。設定切替の連続確定要求は順に直列化し、処理順の最新DataStore値を読み直して最後の選択を反映する。
- TIFのEPG取得では局ごとのquery前に取消状態を確認する。チューナー入力がありREAD_TV_LISTINGSを失った場合は旧TIFキャッシュを番組表・検索・選局候補へ公開せず、番組表画面に権限と設定導線を案内する。権限再許可後に取得し直す。HDMI等パススルー入力だけの場合は権限エラーにせず「番組表がありません」と表示する。入力削除・スキャン後はTIF番組表示・ホームのピックアップ・検索結果を破棄し60秒の間引きを無視して再取得する。検索は現在公開されている完全なチャンネルIDと照合する。TIF取得の旧ファイルキャッシュを先に成功表示せず、読み出さないTIF EPGをディスクへも書かない。
- EPGキャッシュは開始時のbackendと同じbackendへルーティングして取得し、取得後の現行backend確認を通ってから公開・保存する。TIF入力の権限・チューナー有無はTIFアダプターで判定し、ViewModel／EPGキャッシュ層で別途入力を重複列挙しない。TIFの検索キャッシュはチャンネル別の取得成功区間と、共有する実際のTvProvider照会開始時の発行順を保持し、同じ区間では新しい照会を優先する。公開局一覧と局名も照会開始順で保持し、旧照会の後着による追加局の消失・削除局の復活を禁止する。先行した7日照会が遅れて完了した場合も、後から取得した3日分を巻き戻さず、4〜7日目を補完する。局別の失敗区間には照会開始順を付け、より古い成功応答によって新しい失敗区間を解除しない。失敗区間の重複・包含は結合し、成功済み局の取得範囲と区間外の番組を破棄しない。区間が離れた場合は空白を取得済みにせず、過去分は直近24時間を超えて蓄積しない。保持期限（終了から24時間以上経過）より前だけを要求したTIF照会はメモリキャッシュに代入せず要求結果を直接返し、現在の別期間キャッシュへ差し替えない。取得時の保持期限判定とDispatchers.Defaultでの保存可否は同じ基準時刻を共有し、24時間境界を跨ぐ競合でも判定を揃える。ホームの3日取得は検索用7日取得を縮めず、正常0局の共有7日取得を短い待機者が3日へ縮めない。0局キャッシュは同一更新直後のみ再利用し、10秒後の先読みでは再スキャン済みの局を再列挙する。全局照会失敗は旧応答の局集合で即断せず、最新公開局の結合結果に表示可能な番組が残るかを確認してから通知する。入力更新前に開始した旧クエリは世代照合で破棄する。プロキシの選択値をディスク読込後に取り直さない。旧形式のbackend帰属不明キャッシュは他backendへの混入を避けるため意図的に失効させ、再取得する。更新直後でネットワーク接続がない場合、旧キャッシュを使ったオフライン番組表示はできない。
- AI録画再生は要求実行時にbackendを確認し、TIF選択時はネットワーク専用の録画プレイヤーを起動しない。
- EPG検索は当該バックエンドのキャッシュだけを使う。検索・slice変換・野球の日付更新ジョブは取消しと公開前照合を行い、旧結果による上書きを防ぐ。野球の通常集計側も集計時と公開時の日付を比較し、古い日付の結果を再公開しない。
- 全件同期とスマート同期の辞書Job起動・登録は同じ既存mutexで排他し、実行中Job参照を上書きしない。新しい全件同期では旧辞書Jobを停止・待機してから進捗を更新する。通常同期と競合する辞書Jobの開始・件数更新・早期終了・finallyのすべての進捗変更は、開始時同期世代と既存StateFlowの条件付きCASで管理し、新しい同期エラーを後出しで消さない。切替時も終了を待つ。
- 録画履歴は旧`watch_history`テーブルを保持したまま、Room v15→v16の追加マイグレーションで`backend_watch_history`（backend＋recordId複合主キー、履歴JSON・視聴時刻）を追加する。API取得開始時のbackendと履歴データを単一Room行に保存し、別backendの同一数値IDを併存可能にする。帰属を検証できない旧履歴は推測移行せず、誤再生しない。クリック時はbackend付き履歴と現backendの録画DB実体をIDで直接検証し、ホーム最新20件の表示上限に依存せず再開する。バックエンド切替時は既存録画同期・辞書処理を終了し、旧backend固有の録画一覧キャッシュ・辞書・同期進捗だけをRoomトランザクションで無効化する。切替前に永続的な切替中マーカーを記録し、プロセス再起動後は録画キャッシュの帰属先と選択backendが一致するまで一覧・詳細・ページングを非公開にする。旧版に帰属マーカーがない場合は、保存済み録画を選択backend由来と**推測せず**全件再構築する。同一backendの所有者マーカーがあり未完了の同期は、保存済みページから再開する。設定保存失敗時はRoom更新をロールバックして切替前の公開状態を復元し、設定画面に失敗を通知する。視聴履歴・最終視聴・EPGキャッシュなど他の永続テーブルは消去しない。録画履歴はRoomから取得した行とbackend帰属を同じFlow値で公開し、切替時に旧backendのカードを新backendの録画と取り違えない。ホーム・ビデオの履歴選局は同じ帰属付き録画実体確認経路を通し、ビデオタブの「最近の録画」を後から選んだ場合も、先行履歴の遅延応答を再生へ反映しない。切替後は新backendの同期成功時にだけ録画キャッシュを表示可能にし、旧録画を公開しない。録画シリーズの取得・集計結果公開と切替時破棄は共通排他で直列化する。TIFでは録画同期しない。
- RecordViewModel・RecordSyncEngine・録画同期の明示的な入口では、TIF時の録画同期・全再構築を実行しない。録画情報0件を「初期構築完了」として記録しない。
- TIF時は録画／予約タブ・EPG予約・AI録画／録画再生を無効化する。ビデオタブのSMB動画は録画DBが空でも再生可能とする。

## インストールと利用

1. **初回登録**は端末の標準Live TV／TV入力設定で対象TISをセットアップ・スキャンし、TvProviderへの登録とbrowsable設定を済ませる。通常APKからTISのセットアップActivityを直接起動するだけでは、この権限付与・公開設定を代行できない。
2. `adb install -r`で通常APKのKomorebiを導入する。priv-app化しない。
3. 設定で「TV Input Framework」を選ぶ。Komorebiの「TV入力の再設定・スキャン」からの直接起動は**登録済み入力の再設定・再スキャン用**とする。HDMIのみならスキャン不要。
4. チューナーの公開チャンネル・番組表が必要な場合は`READ_TV_LISTINGS`を実行時許可し、許可後にチャンネルと現在番組を再取得する。HDMI等だけなら要求しない。
5. ライブ画面から公開チャンネルか外部入力を選ぶ。入力が見つからない場合は確認エラーを表示し、別入力への黙った代替選局をしない。

`READ_TV_LISTINGS`はdangerous権限。`ACCESS_ALL_EPG_DATA`、`ACCESS_TV_TUNER`、`TUNER_RESOURCE_ACCESS`等の特権権限はKomorebiへ付与しない。

## 対象外

TIS自体の変更、HAL/CAS直接操作、TIF録画・予約、デュアルTIFライブ、独自SI/EIT収集・字幕復号エンジン。TISの`canRecord=true`はKomorebiの録画実装を意味せず、ネットワークの録画経路へ誤転送しない。
